## 1. 项目背景

ArmorHelper v1 是一套把「一张 128×80 的小模板」自动展开成泰拉瑞亚整套护甲贴图的工具，
美术只需画一张图，无需重复绘制 20 帧的每一层。

但泰拉瑞亚自 **1.4.4** 起重写了玩家渲染管线（composite player rendering），贴图格式发生
**不兼容变更**：

* 手臂不再有独立贴图，而是与身体合并为一张 **9 列 × 4 行** 的九宫格；
* 引擎按「部位 + 动作帧」的坐标去索引格子，而不是按 20 帧竖排；
* 身体上下晃动（bob）由引擎负责，不再由贴图烘死。

因此 v1 的输出在 1.4.4+ 中完全不可用。本项目以 **新版泰拉为准**，用 Python 重写该工具，
并保持原有的模板格式与工作流不变。

## 2. 目标与范围

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G-1 | 保留 ArmorHelper v1 的输入模板格式（128×80）与画图流程，美术无需重学 |
| G-2 | 输出符合泰拉 1.4.4+ 新格式的头部、腿部、身体（复合）贴图，可直接放入游戏资源包 |
| G-3 | 同时保留旧格式（≤1.4.3）输出能力，兼容老模组 |
| G-4 | 提供中文图形界面与命令行两种使用方式 |
| G-5 | 保留 v1 的预览与 GIF 功能（全身护甲、全身护甲+玩家） |
| G-6 | 旧格式输出与 v1 逐像素一致，可回归验证 |
| G-7 | 支持反向还原：由原版护甲 id / 贴图还原出 128×80 的绘制模板 |

### 2.2 范围内

* 模板图 → 护甲贴图的转换
* 原版护甲贴图 → 模板图的**反向还原**
* 贴图命名规则（自定义名 / 原版 ID 名）
* 预览图与 GIF 导出
* 中文图形界面（wxPython）
* 命令行接口
* 配置持久化
* 贴图格式检查工具

### 2.3 范围外

* `.xnb` 解包 / 打包（用户需自备已解包的 PNG 资源目录）
* 游戏内运行时校验、TModLoader 模组打包
* 染料、发光遮罩的美术绘制（工具只提供结构）
* 除头部/身体/腿部之外的部位（翅膀、坐骑、时装等）

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 模板（Template） | 128×80 的输入图片，包含头、身体、手臂、腿等所有部位的素材 |
| 帧（Frame） | 逻辑上一帧动作，尺寸 20×28（1×），游戏中为 40×56（2×，native） |
| 逻辑坐标 / 1× | 20×28 一帧的坐标系，v1 全程在此坐标系工作，最后统一放大 2 倍 |
| native / 2× | 游戏实际贴图坐标系，40×56 一帧 |
| 复合贴图（Composite） | 1.4.4+ 的身体贴图，把躯干、肩、双臂、男女版本合并在 9×4 网格里 |
| 格子（Cell） | 复合贴图中的一格，native 尺寸 40×56，用 `(列, 行)` 表示，列/行从 0 起 |
| 正向 / 反向 | 正向 = 模板 → 游戏贴图；反向 = 游戏贴图 → 模板 |
| 套装表 | `data/armor_sets.json`，记录同一套护甲的 head/body/legs 三个护甲槽 ID |
| 发光遮罩（Glow Mask） | 复合贴图第 4~7 行，引擎以 +224px 偏移采样，用于自发光护甲 |
| bob | 走路时身体上下起伏，对应 `Main.OffsetsPlayerHeadgear` |
| 目标（Target） | 一次导出中可以勾选的一种产物，见第 8.1 节 |

## 4. 总体描述

### 4.1 用户角色

| 角色 | 说明 | 主要使用方式 |
|---|---|---|
| 美术 / 模组作者 | 画护甲、导出贴图 | 图形界面 |
| 进阶用户 / 构建脚本 | 批量生成、CI | 命令行 |

### 4.2 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows / macOS / Linux（GUI 需桌面环境） |
| Python | ≥ 3.10 |
| 必需依赖 | Pillow ≥ 9.0 |
| 图形界面依赖 | wxPython ≥ 4.2（可选） |
| 测试依赖 | pytest ≥ 7（可选） |

### 4.3 假设与约束

* 输入模板必须严格为 128×80，否则报错并拒绝处理（与 v1 行为一致）。
* 模板中的像素规则：**alpha ≤ 1 的像素视为透明，永远不覆盖目标**（与 v1 的 `Copy` 一致）。
* 未做防抖的 `Fill` 语义：直接覆盖（含 alpha）。
* GUI 的「全身护甲 + 玩家」预览需要泰拉 `Content/Images` 下的 **PNG** 玩家贴图；
  找不到时给出提示并跳过该产物，不影响其余导出。
* 所有插值必须使用最近邻（Nearest），不得引入抗锯齿。

## 5. 输入规格

### 5.1 模板文件

* 文件名：`ArmorTemplate_v1.png`（可任意改名）
* 尺寸：**严格 128×80**，RGBA
* 模板随程序分发，路径：`armorhelper/data/ArmorTemplate_v1.png`
* 获取方式：
  1. 图形界面启动时若当前目录无 `ArmorTemplate_v1.png`，自动写出一份（与 v1 行为一致）；
  2. 界面「保存模板...」按钮 / 菜单「模板 → 保存绘制模板...」；
  3. 命令行 `python3 -m armorhelper template -o 路径`。

### 5.2 模板区域定义

所有坐标以模板左上角为原点，格式 `(x, y, w, h)`。

| 区域 | 坐标 | 说明 |
|---|---|---|
| 头部 | `(1, 19, 20, 28)` | 复制到全部 20 帧 |
| 男性躯干 | `(23, 19, 20, 28)` | 常规帧 |
| 男性躯干（跳跃） | `(23, 48, 20, 28)` | 仅第 5 帧 |
| 女性躯干 | `(44, 19, 20, 28)` | 常规帧 |
| 女性躯干（跳跃） | `(44, 48, 20, 28)` | 仅第 5 帧 |
| 前臂姿态 0 | `(1, 1, 12, 16)` | 第 0 帧 |
| 前臂姿态 1 | `(14, 1, 12, 16)` | 第 1 帧、第 5 帧 |
| 前臂姿态 2 | `(27, 1, 16, 16)` | 第 2 帧 |
| 前臂姿态 3 | `(44, 1, 17, 16)` | 第 3 帧 |
| 前臂姿态 4 | `(62, 1, 16, 16)` | 第 4 帧 |
| 行走前臂 | `(79, 1, 13, 11)` | 第 6~19 帧，配合逐帧横向偏移 |
| 后臂 | `(94, 1, 12, 11)` | 第 0~19 帧 |
| 后臂补点 | `(101, 8, 1, 1)` | 第 15、16 帧额外补的 1 像素 |
| 左腿素材 | `(66, 19 + 10m, 16, 9)`，m=0..4 | |
| 右腿素材 | `(83, 19 + 10m, 16, 9)`，m=0..4 | |
| 前脚 | `(100, 19, 9, 9)` | |
| 后脚 | `(110, 19, 9, 9)` | |

> 前臂姿态在帧内的落点（v1 原值）：
> 帧0 `(0,9)`、帧1 `(0,5)`、帧2 `(2,5)`、帧3 `(2,8)`、帧4 `(2,9)`、帧5 `(0,5)`。

### 5.3 输入校验

| 条件 | 处理 |
|---|---|
| 文件不存在 | 报错：`输入图片不存在` |
| 非图片 / 损坏 | 报错：`无法读取该文件` |
| 尺寸 ≠ 128×80 | 报错：`输入尺寸错误（期望 128×80，实际 WxH）` |
| 格式为 BMP / PNG | 均接受（Pillow 支持） |
| 批量输入中单个文件失败 | 记录错误并继续处理其余文件；最终返回非 0 退出码 |

## 6. 输出规格

### 6.1 新版（1.4.4+）贴图总览

| 产物 | 放置路径 | 尺寸 | 说明 |
|---|---|---|---|
| 头部 | `Content/Images/Armor_Head_<id>.png` | 40 × 1120 | 20 帧，每帧 40×56 |
| 腿部 | `Content/Images/Armor_Legs_<id>.png` | 40 × 1120 | 20 帧，每帧 40×56 |
| 身体 | `Content/Images/Armor/Armor_<id>.png` | 360 × 224 | 9 列 × 4 行，每格 40×56 |
| 身体（含发光） | 同上 | 360 × 448 | 第 4~7 行为发光遮罩 |

### 6.2 头部贴图

* 尺寸 40×1120，20 帧竖排。
* 每帧内容 = 模板头部区域，按 `BODY_HEAD_OFFSETS` 逐帧纵向偏移（**保留 bob**，
  因为引擎不对头部施加 `OffsetsPlayerHeadgear`）。
* 与 v1 输出的头部贴图**逐像素一致**。

### 6.3 腿部贴图

* 尺寸 40×1120，20 帧竖排。
* 由 10 块腿部素材 + 2 块脚部素材按 `LEG_MAPPING` 映射到 20 帧，**不施加 bob**。
* 与 v1 输出的腿部贴图**逐像素一致**。

### 6.4 身体复合贴图（核心）

列/行均从 0 开始，`(列, 行)` 表示第 列 列、第 行 行。

| 格子 | 内容 |
|---|---|
| `(0,0)` | 男性躯干 |
| `(1,0)` | 男性躯干 · 第 5 帧（跳跃） |
| `(0,2)` | 女性躯干 |
| `(1,2)` | 女性躯干 · 第 5 帧（跳跃） |
| `(0,1)` / `(1,1)` | 男性前肩 / 后肩 |
| `(0,3)` / `(1,3)` | 女性前肩 / 后肩 |
| `(2..6, 0)` | 前臂，对应身体帧 0~4 |
| `(2..6, 1)` | 前臂，对应身体帧 5~19（分组复用） |
| `(2..6, 2)` | 后臂，对应身体帧 0~4 |
| `(2..6, 3)` | 后臂，对应身体帧 5~19（分组复用） |
| `(7, 0..3)` | 挥动道具时的前臂，4 行 = 4 档伸缩 |
| `(8, 0..3)` | 挥动道具时的后臂，4 行 = 4 档伸缩 |

**身体帧 → 前臂格子** 映射（依据 `PlayerDrawSet.CreateCompositeData`）：

| 身体帧 | 格子 | | 身体帧 | 格子 |
|---|---|---|---|---|
| 0 | (2,0) | | 11,12,13 | (3,1) |
| 1 | (3,0) | | 14 | (5,1) |
| 2 | (4,0) | | 15,16 | (6,1) |
| 3 | (5,0) | | 17 | (5,1) |
| 4 | (6,0) | | 18,19 | (3,1) |
| 5 | (2,1) | | | |
| 6 | (3,1) | | | |
| 7,8,9,10 | (4,1) | | | |

**后臂格子 = 同列，行 + 2。**

**生成规则**

| 编号 | 规则 |
|---|---|
| R-1 | 躯干格直接放模板躯干素材，不拆分肩部 |
| R-2 | 肩部格 `(0,1)(1,1)(0,3)(1,3)` **留空**（模板躯干已含肩与上臂，引擎绘制顺序为「后臂 → 躯干 → 前臂」，留空即可复现旧观感） |
| R-3 | 手臂格放在与 v1 旧 20×28 帧内**完全相同**的位置（引擎中手臂的 position 与 origin 同步偏移，净位移为 0，故无需补偿） |
| R-4 | 第 6~19 帧手臂纵向固定为 `y = 12`；v1 中的 `12 + BODY_HEAD_OFFSETS[帧]` 用于抵消 bob，而 1.4.4+ 的 bob 由引擎统一施加 |
| R-5 | 第 3、4、5 帧后臂保持为空（与 v1 一致） |
| R-6 | 同一格子被多帧共用时，取**编号最小**的那一帧的偏移量 |
| R-7 | 第 15、16 帧的「后臂补点」按绝对坐标 `(14, 18)` 写入，不随 bob 偏移（复刻 v1 行为） |
| R-8 | 第 7~10 帧共用的后臂格存在 1 像素的固有偏差（帧 10 期望左偏 1px），新版格式无法表达，取多数值 |

### 6.5 发光遮罩

* 开启后身体贴图高度变为 448，第 4~7 行 = 第 0~3 行的副本。
* 引擎以 `+224px`（即 4 行）偏移采样发光层，故行号必须严格对应。
* 用途：生成「整体发光」的底稿，美术再擦除不需要发光的部分。

### 6.6 旧版（≤1.4.3）兼容输出

| 产物 | 尺寸 | 说明 |
|---|---|---|
| `<name>_BodyLegacy.png` | 40×1120 | 男性身体（后臂 + 躯干 + 前臂） |
| `<name>_BodyLegacyFemale.png` | 40×1120 | 女性身体 |
| `<name>_ArmsLegacy.png` | 40×1120 | 仅前臂 |

要求：与 v1 输出**逐像素一致**（含后臂裁剪、忽略像素、补点等历史行为）。

### 6.7 预览与 GIF

| 产物 | 尺寸 | 说明 |
|---|---|---|
| `<name>_FullArmor.png` | 40×1120 | 20 帧叠合结果 |
| `<name>_FullArmorFemale.png` | 40×1120 | |
| `<name>_FullArmorPlayer.png` | 40×1120 | 玩家皮肤（乘以肤色 255,150,89）垫底后叠加护甲 |
| `<name>_FullArmorPlayerFemale.png` | 40×1120 | |
| 同名 `.gif` | 40×56 每帧 | 共 52 帧序列，帧延时 66ms，循环播放，调色板全帧共享 |

GIF 帧序列（与 v1 一致）：行走两轮（帧 0→19 ×2）→ 停在帧 0 ×4 → 跳跃序列（帧 1→4）
→ 停在帧 0 ×4。

### 6.8 原版套装表（`data/armor_sets.json`）

| 字段 | 说明 |
|---|---|
| `body` / `head` / `legs` | 护甲槽 ID，`head`/`legs` 可能为 `null` |
| `name` | 英文名（`ArmorIDs` 常量名） |
| `zh` | 中文名，取自游戏本地化文件，缺失时为空串 |
| `confidence` | `set-bonus`（来自套装加成，权威）/ `name` / `prefix`（命名规则匹配） |

| 指标 | 数值 |
|---|---|
| 条目总数 | 204 |
| 同时给出头与腿 | 151 |
| 有中文名 | 202 |
| 权威（套装加成）条目 | 23 |

UI 显示格式：`星尘板甲  StardustPlate  (190)`。

### 6.9 反向还原产物

| 产物 | 尺寸 | 说明 |
|---|---|---|
| `<名称>.png` | 128 × 80 | 可直接作为模板再次投入正向流程 |

还原精度（以原版贴图为基准）：

| 部位 | 贴图层一致率 | 说明 |
|---|---|---|
| 头部 | 100% | 无损 |
| 腿部 | 90%~100% | 前后脚贴图在同一帧内互相遮挡，被遮住的少数像素不可观测 |
| 身体（按引擎渲染后的画面比较） | 90%~97% | 模板只有 1 个行走手臂姿态，原版 4 个不同姿态被合并 |

依据：**全部 748 个原版护甲贴图都是 1× 像素画的精确 2 倍最近邻放大**（抽查 2×2 块同色率
为 100%，仅 22 个文件有 0.005%~0.18% 的少量例外像素），因此 128×80 的模板足以描述它们。

### 6.10 文件命名规则

| 场景 | 命名 |
|---|---|
| 未指定 ID | `<输入文件名去扩展名>_Head.png`、`_Legs.png`、`_Body.png`、`_BodyLegacy.png`、`_BodyLegacyFemale.png`、`_ArmsLegacy.png` |
| 指定 ID | `Armor_Head_<headId>.png`、`Armor_Legs_<legsId>.png`、`Armor/Armor_<bodyId>.png`、`Armor_Body_<bodyId>.png`、`Female_Body_<bodyId>.png`、`Armor_Arm_<bodyId>.png` |
| 未指定 id_head / id_legs 但指定了 id_body | 头/腿沿用身体 ID |
| 预览 | `<名称>_FullArmor[...].png` / `.gif` |

身体贴图默认放入子目录 `Armor/`，可用 `--body-subdir` 修改。

### 附录 B：引擎侧的绘制顺序与偏移

| 顺序 | 调用 | 内容 |
|---|---|---|
| 1 | `DrawPlayer_13_Leggings` | 腿部 |
| 2 | `DrawPlayer_12_Skin` / `_BackArmShirt` | 后臂（含护甲后臂） |
| 3 | `DrawPlayer_17_Torso` | 躯干 |
| 4 | `DrawPlayer_19_FrontArm` | 前肩 + 前臂 |
| 5 | `DrawPlayer_21_Head` | 头部 |

* 手臂 `GetCompositeOffset_FrontArm = (-5, 0)`、`GetCompositeOffset_BackArm = (6, 2)`，
  但 position 与 origin 同步偏移，**净位移为 0**（rotation = 0 时）。
* 躯干/手臂/肩均使用 `Main.OffsetsPlayerHeadgear[帧]`（Y 为 2 或 0），
  即 bob 由引擎统一施加：`Y_engine = 2 + 2 × (−BODY_HEAD_OFFSETS)`。
* 头部**不**使用 `OffsetsPlayerHeadgear`，因此 bob 必须烘进头部贴图。
* 发光层采样偏移：`sourceRect.Y += 224`。

### 附录 C：反向还原的不可恢复项

| 项目 | 原因 | 影响 |
|---|---|---|
| 后脚第 21 行的部分像素 | 生成器对该行两个源像素做了屏蔽，且后脚始终被前脚遮挡 | 无——重建时会再次跳过/被前脚覆盖 |
| 挥动道具的手臂格（第 7、8 列） | 模板中没有对应区域 | 重建后这两列由第 0 帧手臂填充 |
| 肩部格（0,1)(1,1)(0,3)(1,3) | 模板中没有对应区域 | 还原时把肩部合并进躯干格，渲染效果基本一致 |
| 原版第 7~10 帧各自的行走手臂 | 模板只有一个行走手臂区域 | 重建后 4 格共用同一姿态，渲染约 3% 差异 |
| 发光遮罩（第 4~7 行） | 模板中没有发光层 | 还原时丢弃；需要发光请用 `--glow` 重新生成底稿 |

### 附录 D：已知限制

| 编号 | 限制 | 说明 |
|---|---|---|
| L-01 | 第 7~10 帧共用的后臂格存在 1 像素偏差 | 新版格式的固有约束，帧 10 期望的后臂比 7~9 帧左移 1 逻辑像素 |
| L-02 | 肩部格留空 | 若美术希望肩部随手臂单独运动，需自行在 `(0,1)(1,1)(0,3)(1,3)` 补充素材 |
| L-03 | `(7,*)(8,*)` 默认用第 0 帧手臂填充 | 只是保证挥动道具时手臂不消失，完美效果需手绘 4 档伸缩姿态 |
| L-04 | 发光遮罩为整体复制 | 需要局部发光时由美术擦除 |
| L-05 | 不支持 `.xnb` 直接读写 | 需使用已解包的 PNG 资源目录 |
