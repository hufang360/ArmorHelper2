## 1. 项目背景

ArmorHelper v1 是一套把「一张 128×80 的小模板」自动展开成泰拉瑞亚整套盔甲贴图的工具，
美术只需画一张图，无需重复绘制 20 帧的每一层。

但泰拉瑞亚自 **1.4.4** 起重写了玩家渲染管线（composite player rendering），贴图格式发生
**不兼容变更**：

* 手臂不再有独立贴图，而是与身体合并为一张 **9 列 × 4 行** 的九宫格；
* 引擎按「部位 + 动作帧」的坐标去索引格子，而不是按 20 帧竖排；
* 身体上下晃动（bob）由引擎负责，不再由贴图烘死。

因此 v1 的输出在 1.4.4+ 中完全不可用。本项目以 **新版泰拉为准**重写该工具，
并保持原有的模板格式与工作流不变。

## 2. 目标与范围

### 2.1 目标

| 编号 | 目标 |
|---|---|
| G-1 | 保留 ArmorHelper v1 的输入模板格式（128×80）与画图流程，美术无需重学 |
| G-2 | 输出符合泰拉 1.4.4+ 新格式的头部、腿部、身体（复合）贴图，可直接放入游戏资源包 |
| G-3 | 同时保留旧格式（≤1.4.3）输出能力，兼容老模组 |
| G-4 | 保留 v1 的预览与 GIF 功能（全身盔甲、全身盔甲+玩家） |
| G-5 | 旧格式输出与 v1 逐像素一致，可回归验证 |
| G-6 | 支持反向还原：由原版盔甲 id / 贴图还原出 128×80 的绘制模板 |

### 2.2 范围内

* 模板图 → 盔甲贴图的转换
* 原版盔甲贴图 → 模板图的**反向还原**
* 贴图命名规则（自定义名 / 原版 ID 名）
* 预览图与 GIF 导出
* 配置持久化
* 贴图格式检查工具

2.0 的图形界面与命令行接口已移除，规格见 [`历史-2.0.md`](历史-2.0.md)。

### 2.3 范围外

* `.xnb` 解包 / 打包（用户需自备已解包的 PNG 资源目录）
* 游戏内运行时校验、TModLoader 模组打包
* 染料、发光遮罩的美术绘制（工具只提供结构）
* 除头部/身体/腿部之外的部位（翅膀、坐骑、时装等）

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 模板（Template） | 128×80 的输入图片，包含头、身体、手臂、腿等所有部位的素材 |
| 帧（Frame） | 逻辑上一帧动作，尺寸 20×28（1×），游戏中为 40×56（2×，native） |
| 逻辑坐标 / 1× | 20×28 一帧的坐标系，v1 全程在此坐标系工作，最后统一放大 2 倍 |
| native / 2× | 游戏实际贴图坐标系，40×56 一帧 |
| 复合贴图（Composite） | 1.4.4+ 的身体贴图，把躯干、肩、双臂、男女版本合并在 9×4 网格里 |
| 格子（Cell） | 复合贴图中的一格，native 尺寸 40×56，用 `(列, 行)` 表示，列/行从 0 起 |
| 正向 / 反向 | 正向 = 模板 → 游戏贴图；反向 = 游戏贴图 → 模板 |
| 套装表 | `data/armor_sets.json`，记录同一套盔甲的 head/body/legs 三个盔甲槽 ID |
| 发光遮罩（Glow Mask） | 复合贴图第 4~7 行，引擎以 +224px 偏移采样，用于自发光盔甲 |
| bob | 走路时身体上下起伏，对应 `Main.OffsetsPlayerHeadgear` |
| 目标（Target） | 一次导出中可以勾选的一种产物，见第 7 节 |

## 4. 通用约定

* 输入模板必须严格为 128×80，否则报错并拒绝处理（与 v1 行为一致）。
* 模板中的像素规则：**alpha ≤ 1 的像素视为透明，永远不覆盖目标**（与 v1 的 `Copy` 一致）。
* 未做防抖的 `Fill` 语义：直接覆盖（含 alpha）。
* 「叠加玩家」预览需要玩家贴图 `Player_0_3 / 0_7 / 0_10.png`。内置了一份，用户选了
  `Content/Images` 时优先用用户的；找不到时给出提示并跳过该产物，不影响其余导出。
* 所有插值必须使用最近邻（Nearest），不得引入抗锯齿。

## 5. 输入规格

### 5.1 模板文件

* 文件名：`ArmorTemplate_v1.png`（可任意改名）
* 尺寸：**严格 128×80**，RGBA
* 模板随程序分发，路径：`web/data/ArmorTemplate_v1.png`
* 获取方式：导出页的「来个 Demo」载入它，拖放区右上角的下载图标可导出当前画面（按参考线开关决定是否叠加）。
  2.0 的「启动时自动写出一份」、桌面「保存模板...」与 `template` 子命令都已移除。

**模板里没有空闲像素**：区域之外还有 4395 个不透明像素，全部是参考线。想给「4 个行走手臂
姿态」或肩部单独划区域，只能重画模板 —— 那会破坏「与 v1 同一张模板」的兼容目标，
而且 `web/tests/golden/` 要整批重做。故此事一直被否决（限制见附录 E 的 L-02）。

### 5.2 模板区域定义

所有坐标以模板左上角为原点，格式 `(x, y, w, h)`。

```text
      x:  1        23        44        66      83  100 110
 y  1     +---------+---------+---------+-------+---+---+
          | 5 个前臂姿态      | 行走臂 | 后臂          |
 y 19     +---------+---------+---------+-------+---+---+
          |  头部   |  身体   |  女性   |  腿   | 脚    |
          |         |         |         |       |       |
 y 48     +         + 跳跃    + 跳跃    +       +       +
```

| 区域 | 坐标 | 说明 |
|---|---|---|
| 头部 | `(1, 19, 20, 28)` | 复制到全部 20 帧 |
| 男性躯干 | `(23, 19, 20, 28)` | 常规帧 |
| 男性躯干（跳跃） | `(23, 48, 20, 28)` | 仅第 5 帧 |
| 女性躯干 | `(44, 19, 20, 28)` | 常规帧 |
| 女性躯干（跳跃） | `(44, 48, 20, 28)` | 仅第 5 帧 |
| 前臂姿态 0 | `(1, 1, 12, 16)` | 第 0 帧 |
| 前臂姿态 1 | `(14, 1, 12, 16)` | 第 1 帧、第 5 帧 |
| 前臂姿态 2 | `(27, 1, 16, 16)` | 第 2 帧 |
| 前臂姿态 3 | `(44, 1, 17, 16)` | 第 3 帧 |
| 前臂姿态 4 | `(62, 1, 16, 16)` | 第 4 帧 |
| 行走前臂 | `(79, 1, 13, 11)` | 第 6~19 帧，配合逐帧横向偏移 |
| 后臂 | `(94, 1, 12, 11)` | 第 0~19 帧 |
| 后臂补点 | `(101, 8, 1, 1)` | 第 15、16 帧额外补的 1 像素 |
| 左腿素材 | `(66, 19 + 10m, 16, 9)`，m=0..4 | |
| 右腿素材 | `(83, 19 + 10m, 16, 9)`，m=0..4 | |
| 前脚 | `(100, 19, 9, 9)` | |
| 后脚 | `(110, 19, 9, 9)` | |

> 前臂姿态在帧内的落点（v1 原值）：
> 帧0 `(0,9)`、帧1 `(0,5)`、帧2 `(2,5)`、帧3 `(2,8)`、帧4 `(2,9)`、帧5 `(0,5)`。

逐帧偏移表（`frontArmOffsets`、`backArmOffsets`、`bodyHeadOffsets`、`legMapping`）原样照搬 v1，
存在 `web/data/layout.json`，由 `web/js/` 读取。网页版不重新实现常量。

### 5.3 输入校验

| 条件 | 处理 |
|---|---|
| 文件不存在 | 报错：`输入图片不存在` |
| 非图片 / 损坏 | 报错：`无法读取该文件` |
| 尺寸 ≠ 128×80 | 报错：`输入尺寸错误（期望 128×80，实际 WxH）` |
| 格式为 PNG / WebP | 只接受这两种；BMP 不再支持 |
| 批量输入中单个文件失败 | 记录错误并继续处理其余文件 |

## 6. 输出规格

### 6.1 新版（1.4.4+）贴图总览

| 产物 | 放置路径 | 尺寸 | 说明 |
|---|---|---|---|
| 头部 | `Content/Images/Armor_Head_<id>.png` | 40 × 1120 | 20 帧，每帧 40×56 |
| 腿部 | `Content/Images/Armor_Legs_<id>.png` | 40 × 1120 | 20 帧，每帧 40×56 |
| 身体 | `Content/Images/Armor/Armor_<id>.png` | 360 × 224 | 9 列 × 4 行，每格 40×56 |
| 身体（含发光） | 同上 | 360 × 448 | 第 4~7 行为发光遮罩 |

### 6.2 头部贴图

* 尺寸 40×1120，20 帧竖排。
* 每帧内容 = 模板头部区域，按 `BODY_HEAD_OFFSETS` 逐帧纵向偏移（**保留 bob**，
  因为引擎不对头部施加 `OffsetsPlayerHeadgear`）。
* 与 v1 输出的头部贴图**逐像素一致**。

### 6.3 腿部贴图

* 尺寸 40×1120，20 帧竖排。
* 由 10 块腿部素材 + 2 块脚部素材按 `LEG_MAPPING` 映射到 20 帧，**不施加 bob**。
* 与 v1 输出的腿部贴图**逐像素一致**。

### 6.4 身体复合贴图（核心）

列/行均从 0 开始，`(列, 行)` 表示第 列 列、第 行 行。

| 格子 | 内容 |
|---|---|
| `(0,0)` | 男性躯干 |
| `(1,0)` | 男性躯干 · 第 5 帧（跳跃） |
| `(0,2)` | 女性躯干 |
| `(1,2)` | 女性躯干 · 第 5 帧（跳跃） |
| `(0,1)` / `(1,1)` | 男性前肩 / 后肩 |
| `(0,3)` / `(1,3)` | 女性前肩 / 后肩 |
| `(2..6, 0)` | 前臂，对应身体帧 0~4 |
| `(2..6, 1)` | 前臂，对应身体帧 5~19（分组复用） |
| `(2..6, 2)` | 后臂，对应身体帧 0~4 |
| `(2..6, 3)` | 后臂，对应身体帧 5~19（分组复用） |
| `(7, 0..3)` | 挥动道具时的前臂，4 行 = 4 档伸缩 |
| `(8, 0..3)` | 挥动道具时的后臂，4 行 = 4 档伸缩 |

**身体帧 → 前臂格子** 映射（依据 `PlayerDrawSet.CreateCompositeData`）：

| 身体帧 | 格子 | | 身体帧 | 格子 |
|---|---|---|---|---|
| 0 | (2,0) | | 11,12,13 | (3,1) |
| 1 | (3,0) | | 14 | (5,1) |
| 2 | (4,0) | | 15,16 | (6,1) |
| 3 | (5,0) | | 17 | (5,1) |
| 4 | (6,0) | | 18,19 | (3,1) |
| 5 | (2,1) | | | |
| 6 | (3,1) | | | |
| 7,8,9,10 | (4,1) | | | |

**后臂格子 = 同列，行 + 2。**

#### 生成规则

| 编号 | 规则 |
|---|---|
| R-1 | 躯干格直接放模板躯干素材，不拆分肩部 |
| R-2 | 肩部格 `(0,1)(1,1)(0,3)(1,3)` **留空**（模板躯干已含肩与上臂，引擎绘制顺序为「后臂 → 躯干 → 前臂」，留空即可复现旧观感） |
| R-3 | 手臂格放在与 v1 旧 20×28 帧内**完全相同**的位置（引擎中手臂的 position 与 origin 同步偏移，净位移为 0，故无需补偿） |
| R-4 | 第 6~19 帧手臂纵向固定为 `y = 12`；v1 中的 `12 + BODY_HEAD_OFFSETS[帧]` 用于抵消 bob，而 1.4.4+ 的 bob 由引擎统一施加 |
| R-5 | 第 3、4、5 帧后臂保持为空（与 v1 一致） |
| R-6 | 同一格子被多帧共用时，取**编号最小**的那一帧的偏移量 |
| R-7 | 第 15、16 帧的「后臂补点」按绝对坐标 `(14, 18)` 写入，不随 bob 偏移（复刻 v1 行为） |
| R-8 | 第 7~10 帧共用的后臂格存在 1 像素的固有偏差（帧 10 期望左偏 1px），新版格式无法表达，取多数值 |

其它共用格的帧（`7~10`、`11~13`、`18~19`）在 v1 里的偏移本来就相同，所以复用不损失信息；
唯一的例外是 R-8（即附录 E 的 L-01）。

### 6.5 发光遮罩

* 开启后身体贴图高度变为 448，第 4~7 行 = 第 0~3 行的副本。
* 引擎以 `+224px`（即 4 行）偏移采样发光层，故行号必须严格对应。
* 用途：生成「整体发光」的底稿，美术再擦除不需要发光的部分。

### 6.8 原版套装表（`data/armor_sets.json`）

| 字段 | 说明 |
|---|---|
| `body` / `head` / `legs` | 盔甲槽 ID，`head`/`legs` 可能为 `null` |
| `name` | 英文名（`ArmorIDs` 常量名） |
| `zh` | 中文名，取自游戏本地化文件，缺失时为空串 |
| `confidence` | `set-bonus`（来自套装加成，权威）/ `name` / `prefix`（命名规则匹配） |

| 指标 | 数值 |
|---|---|
| 条目总数 | 204 |
| 同时给出头与腿 | 151 |
| 有中文名 | 202 |
| 权威（套装加成）条目 | 23 |

UI 显示格式：`星尘板甲  StardustPlate  (190)`。

**53 条缺头或缺腿**（其中 13 条 `confidence` 为 `none`）。原版并没有把「套装」存成数据，
只能靠套装加成表 + 命名规则推导，而 robe / 时装类套装的三个槽位命名往往不成套。
UI 会显示推导结果供核对，也可手动覆盖头 / 腿 ID。

不能用「连续 item id」猜同一套：原版不连续（铜盔甲是 89 / 80 / 76），噪声太大；
`Item.cs` 的 `bodySlot = N` + 相邻 id 分组同样受此影响，且 `case` 块嵌套会让窗口式解析误配。
只保留其中「body slot → item id → 本地化名」这一步用于取中文名，分组仍靠套装加成表 + 命名。

### 6.9 反向还原产物

单套还原写入「输出目录」；批量还原（「还原全部套装」）写入
**`<输出目录>/ArmorTemplate/`**，文件名 `ArmorTemplate_<中文名>_<身体ID>.png`。
只处理 head/body/legs 三个贴图都存在的套装（当前贴图集为 150/151 套）。

| 产物 | 尺寸 | 说明 |
|---|---|---|
| `<名称>.png` | 128 × 80 | 可直接作为模板再次投入正向流程 |

还原精度（以原版贴图为基准）：

| 部位 | 贴图层一致率 | 说明 |
|---|---|---|
| 头部 | 100% | 无损 |
| 腿部 | 90%~100% | 前后脚贴图在同一帧内互相遮挡，被遮住的少数像素不可观测 |
| 身体（按引擎渲染后的画面比较） | 90%~97% | 模板只有 1 个行走手臂姿态，原版 4 个不同姿态被合并 |

依据：**全部 748 个原版盔甲贴图都是 1× 像素画的精确 2 倍最近邻放大**（抽查 2×2 块同色率
为 100%，仅 22 个文件有 0.005%~0.18% 的少量例外像素），因此 128×80 的模板足以描述它们。

### 6.10 成品贴图 → 全身帧/GIF（不经模板）

除了「模板 → 贴图」，还需要反方向快速预览：手上有三张成品贴图（原版、材质包、
别人的作品）时，直接合成 20 帧全身动画。

* 入口：预览贴图页的三个槽位（拖入或点选）；「反向还原」页可直接用内置贴图。
* 部位识别：文件名含 `head/helm/hat` → 头部，`leg/greave/boot` → 腿部，
  `body/armor/torso/chest/breastplate` → 身体；`Player_*` 明确排除。
  ID 取文件名末尾的 `_<数字>`。识别失败但图是宽图时按身体处理；槽位仍可由用户直接指定。
* 尺寸校验：头部 / 腿部为 `20×28` 的整数倍（每帧竖排 20 帧），身体为 9 列 × 4 行
  （发光版 9×8 只取前 4 行）。1× 素材自动放大到 2×，混用尺度时统一到最大格子。
* 绘制顺序与引擎一致（见附录 B）：腿 → 后肩 → 后臂 → 躯干 → 前肩 → 前臂 → 头。
* 产物：`<名称>_FullArmor.png/.gif`、`<名称>_FullArmorFemale.png/.gif`；
  提供 `Content/Images` 时额外输出 `*Player*` 变体。`<名称>` 默认 `Armor_<身体ID>`。
* 与反向还原的区别：反推模板再生成会丢腿/身体的部分像素，本流程直接采样成品贴图，
  结果就是游戏实际画面。

### 6.11 文件命名规则

| 场景 | 命名 |
|---|---|
| 四张原版贴图（头 / 腿 / 身体 / 旧格式） | `Armor_Head_<headId>.png`、`Armor_Legs_<legsId>.png`、`Armor/Armor_<bodyId>.png`、`Armor_Body_<bodyId>.png`、`Female_Body_<bodyId>.png`、`Armor_Arm_<bodyId>.png` |
| ID 留空 | 按 `0` 处理，见上表 |
| 未指定 id_head / id_legs 但指定了 id_body | 头/腿沿用身体 ID |
| 预览与全身图 | `<输入文件名>_FullArmor[...].png` / `.gif` |

身体贴图固定放入子目录 `Armor/`。

### 附录 B：引擎侧的绘制顺序与偏移

| 顺序 | 调用 | 内容 |
|---|---|---|
| 1 | `DrawPlayer_13_Leggings` | 腿部 |
| 2 | `DrawPlayer_12_Skin` / `_BackArmShirt` | 后臂（含盔甲后臂） |
| 3 | `DrawPlayer_17_Torso` | 躯干 |
| 4 | `DrawPlayer_19_FrontArm` | 前肩 + 前臂 |
| 5 | `DrawPlayer_21_Head` | 头部 |

* 手臂 `GetCompositeOffset_FrontArm = (-5, 0)`、`GetCompositeOffset_BackArm = (6, 2)`，
  但 position 与 origin 同步偏移，**净位移为 0**（rotation = 0 时）。
* 躯干/手臂/肩均使用 `Main.OffsetsPlayerHeadgear[帧]`（Y 为 2 或 0），
  即 bob 由引擎统一施加：`Y_engine = 2 + 2 × (−BODY_HEAD_OFFSETS)`。
* 头部**不**使用 `OffsetsPlayerHeadgear`，因此 bob 必须烘进头部贴图。
* 发光层采样偏移：`sourceRect.Y += 224`。

### 附录 C：反向还原的不可恢复项

生成全程是 1× 上的纯像素拷贝、最后整体放大 2×，每一步都可逆，所以反向还原就是生成表的
逆运算：躯干取格子 `(0,0)` `(1,0)` `(0,2)` `(1,2)`，前臂取各帧所属格子的 owner 帧偏移，
行走手臂取 offset 为 0 的格子，后臂取 `(2,2)`，脚部用「第 0 帧 + 第 19 帧」互补恢复
（生成器在第 19 帧交换了两只脚的左右位置）。下面这些丢失项都源于「模板里没有对应区域」。

| 项目 | 原因 | 影响 |
|---|---|---|
| 后脚第 21 行的部分像素 | 生成器对该行两个源像素做了屏蔽，且后脚始终被前脚遮挡 | 无——重建时会再次跳过/被前脚覆盖 |
| 挥动道具的手臂格（第 7、8 列） | 模板中没有对应区域 | 重建后这两列由第 0 帧手臂填充 |
| 肩部格（0,1)(1,1)(0,3)(1,3) | 模板中没有对应区域 | 还原时把肩部合并进躯干格，渲染效果基本一致 |
| 原版第 7~10 帧各自的行走手臂 | 模板只有一个行走手臂区域 | 重建后 4 格共用同一姿态，渲染约 3% 差异 |
| 发光遮罩（第 4~7 行） | 模板中没有发光层 | 还原时丢弃；需要发光请勾「发光遮罩」重新生成底稿 |
